# Внедрение прозрачной статистики и детального логирования ИИ

Данный план описывает реализацию полноценной системы прозрачности работы искусственного интеллекта, включающей сохранение детальных логов запросов (с подсчетом токенов и стоимости), автоматическую очистку устаревших записей, REST API для аналитики и обновленный двухвкладочный интерфейс в панели управления «AI Ключи».

---

## 🛠 Компоненты системы

### 1. База данных (Бэкенд модели)
Создаем модель `AILog` в новом файле `@/Projects/FanpayToolHelper/backend/app/models/ai_log.py`:
- `id` (INT, Primary Key)
- `created_at` (TIMESTAMP, default=UTC Now)
- `key_id` (INT, Foreign Key to `ai_keys.id`, NULL-able)
- `model` (VARCHAR, используемая модель LLM)
- `action_type` (VARCHAR, 'chat_reply', 'profile_audit', 'review_classification')
- `prompt` (TEXT, полный текст системного промпта и истории запроса)
- `response` (TEXT, полученный ответ ИИ, NULL-able)
- `status` (VARCHAR, 'success' или 'error')
- `prompt_tokens` (INT, количество токенов запроса)
- `completion_tokens` (INT, количество токенов ответа)
- `total_tokens` (INT, суммарное количество токенов)
- `error_message` (TEXT, текст ошибки при сбое, NULL-able)
- `account_id` (INT, Foreign Key to `fanpay_accounts.id`, NULL-able)

**Инициализация:**
Импортируем `AILog` в `@/Projects/FanpayToolHelper/backend/app/database.py`, чтобы SQLModel автоматически сгенерировал и применил таблицу `ai_logs` при старте приложения через `init_db`.

---

### 2. Сбор статистики при вызовах ИИ
В сервисе `@/Projects/FanpayToolHelper/backend/app/services/ai.py` расширяем функционал отправки запросов:
- Добавляем асинхронный метод `log_interaction` для быстрой и безопасной записи лога в БД (с обработкой `try...except`, чтобы сбои логирования никогда не ломали работу основного функционала бота).
- В `generate_response` добавляем опциональные параметры `account_id: Optional[int] = None` и `action_type: str = "chat_reply"`.
- При успешном вызове `litellm.acompletion` извлекаем данные об использовании токенов из `response.usage` и записываем успешный лог.
- При возникновении исключений (ошибка авторизации, превышение лимитов, недоступность модели) записываем лог со статусом `error` и подробным описанием ошибки в поле `error_message`.
- Интегрируем аналогичное логирование в метод пакетной классификации отзывов `classify_reviews_batch`.

---

### 3. Автоматическая очистка устаревших логов
В фоновом планировщике `@/Projects/FanpayToolHelper/backend/app/services/scheduler.py`:
- Добавляем периодическую задачу `job_cleanup_old_ai_logs`, которая выполняется каждые 24 часа.
- Метод выполняет SQL-запрос `DELETE FROM ai_logs WHERE created_at < 14 дней назад` для предотвращения неконтролируемого разрастания базы данных.
- Регистрируем данную задачу при запуске планировщика в методе `start()`.

---

### 4. REST API для статистики и логов
Добавляем новые роуты в `@/Projects/FanpayToolHelper/backend/app/api/ai_keys.py` (доступные только администраторам):
- `GET /ai-keys/stats` — возвращает агрегированные данные:
  - Суммарные счетчики (запросы, успешные, сбои, токены).
  - Сгруппированную статистику по моделям (название, число вызовов, токены).
  - Сгруппированную статистику по ключам (маскированное значение, число вызовов, статус, токены).
  - *Расчет стоимости (в скобках/маленьким шрифтом)*: Бэкенд будет рассчитывать примерную стоимость в USD на основе официальных тарифов Fireworks AI для популярных моделей (например, $0.50/1M токенов для Kimi K2.5, $0.90/1M для Llama 3.3 70B и т.д.).
- `GET /ai-keys/logs` — возвращает пагинированный список логов с возможностью фильтрации по статусу, типу действия и лимиту вывода (по умолчанию 50 записей).
- `POST /ai-keys/logs/clear` — эндпоинт для мгновенной принудительной ручной очистки всей таблицы логов по нажатию кнопки администратором.

### 5. Фронтенд-интерфейс (React & Tailwind)
Внедряем вкладки в файл `@/Projects/FanpayToolHelper/frontend/src/components/tabs/AIKeysTab.tsx`:

#### Вкладка 1: «Управление ключами»
- Переносим сюда существующий интерфейс пакетного добавления Fireworks API ключей и интерактивного списка с возможностью переключения активности ключа и удаления.

#### Вкладка 2: «Аналитика и логи ИИ»
- **Панель показателей (Глоссарий)**:
  - Четыре премиальные карточки с градиентным свечением:
    1. **Всего запросов** (с красивым линейным индикатором успешных зеленых и ошибочных красных вызовов).
    2. **Потрачено токенов** (общее число с разбивкой на Prompt / Completion).
    3. **Затраты (USD)** (расчетная стоимость в долларах США с красивой иконкой монет `Coins`).
    4. **Активные ключи** (доля рабочих ключей к общему числу).
- **Сводные таблицы использования**:
  - Компактные стильные списки, показывающие нагрузку по моделям (Kimi, Qwen, Llama) и активность по ключам.
- **Интерактивный список взаимодействия (Аккордеон)**:
  - Отображает логи ИИ в обратном хронологическом порядке.
  - Каждая строчка содержит: *Время*, *Модель*, *Тип действия*, *Токены (и стоимость)*, *Статус (зеленый "Успешно" или красный "Ошибка")*.
  - При клике на строку блок плавно разворачивается (через Framer Motion):
    - **Форматированный чат-контейнер**: промпт и ответ красиво форматируются и разделяются по ролям (Системный промпт - фиолетовый, Сообщение покупателя - синее, Ответ ассистента - зеленый/бирюзовый) с возможностью быстрого копирования текста.
    - В случае ошибки — выводится детальное текстовое поле с ошибкой (красная подсветка) и кнопка быстрого копирования трейсбека для отладки.
- **Инструменты управления**:
  - Кнопка **"Обновить статистику"** (Refresh).
  - Кнопка **"Очистить все логи"** (с модальным окном подтверждения действия).

## 🔍 Интеграция с существующим кодом (Полная совместимость)
- Сигнатуры существующих методов вызова ИИ полностью сохраняются, новые параметры (`account_id`, `action_type`) делаются необязательными со значениями по умолчанию.
- Импорты и таблицы создаются динамически — база данных обновится сама при перезапуске бэкенда.
- Вся верстка фронтенда будет оформлена в глубоком темном премиум-стиле с использованием анимаций `framer-motion` и иконок `lucide-react`.
